# Система автоматической обработки корпоративной почты

Учебный проект по курсу «Технологии программирования» (НИУ ВШЭ, Бизнес-информатика).

Программа автоматически обрабатывает входящие письма IT-отдела: читает файлы
из входной папки, определяет категорию каждого письма по содержанию и раскладывает
письма по папкам категорий. По итогам работы формируются лог и текстовый отчёт.

## Что умеет программа

- Читает письма из входной папки, проверяя формат, размер и кодировку файла
- Разбирает каждое письмо на части: отправитель, получатель, тема, тело
- Чистит текст и приводит русские слова к начальной форме, чтобы надёжно ловить
  ключевые слова в любой их форме
- Определяет категорию письма по ключевым словам, учитывая, в каком поле они
  встретились и насколько слово показательно
- Перемещает письмо в папку нужной категории
- Не падает на «сложных» файлах — пустых, бинарных, картинках, битом JSON.
  Такие файлы спокойно уходят в карантин, а программа продолжает работу
- Собирает итоговый отчёт: сколько писем, по каким категориям, что ушло в карантин

## Категории писем

`incidents_and_alerts` | Инциденты и уведомления мониторинга |
`access_and_user_accounts` | Доступы и учётные записи |
`hardware_requests` | Оборудование и техника |
`software_issues` | Проблемы с программами |
`client_partner_requests` | Клиенты и партнёры |
`docs_finance_contracts` | Документы, финансы и договоры |
`org_info_and_meetings` | Организационные письма и встречи |
`security_spam_phishing` | Спам и подозрительные письма |
`needs_manual_review` | Требует ручного разбора |
`technical_quarantine` | Технический карантин (нечитаемые файлы) |

Отдельно стоит сказать про `needs_manual_review`. Если письмо не набирает
достаточно баллов ни по одной категории — или если две категории идут вровень и
непонятно, какая важнее, — программа не пытается угадать. Она честно откладывает
такое письмо в ручной разбор. Так же поступит и с письмом совершенно нового типа,
которого мы не предусмотрели: оно не потеряется, а просто попадёт человеку.

## Как это устроено

Каждое письмо проходит через цепочку шагов:

```
файл → чтение → разбор на поля → нормализация текста →
классификация → перемещение в папку → запись в отчёт
```

Категорию мы определяем по ключевым словам. Для каждой категории есть свой набор:
«обычные» (например, «принтер», «доступ») и «сильные», по которым
почти наверняка ясна тема (например, «healthcheck», «выиграть»). Сильные слова
весят больше. Кроме того, слово в теме письма значит больше, чем в теле. Программа
складывает баллы и выбирает категорию-лидера, но только если она набрала достаточно
и заметно опережает следующую. Это защищает от случайных совпадений.

Почему не по теме письма, а по содержанию? Потому что тема часто врёт: в одном из
тестовых писем тема была про больничный, а в теле - просьба согласовать отпуск.
Поэтому решающее слово за текстом письма, а не за заголовком.

## Структура проекта

```
mail_classifier_project/
├── src/mail_classifier/
│   ├── main.py            # точка входа, связывает все модули
│   ├── file_scanner.py    # поиск файлов во входной папке
│   ├── email_reader.py    # безопасное чтение файла (форматы, кодировки, размер)
│   ├── email_parser.py    # разбор письма на поля
│   ├── text_normalizer.py # нормализация и лемматизация текста
│   ├── classifier.py      # классификация по ключевым словам
│   ├── router.py          # перемещение файла в папку категории
│   ├── reporter.py        # сбор статистики и формирование отчёта
│   └── rules.py           # категории, маркеры, веса и пороги
├── tests/                 # тесты pytest
├── data/inbox/            # входные письма (в репозитории не хранятся)
├── data/output/           # результат сортировки (создаётся автоматически)
├── logs/                  # логи работы
├── reports/               # итоговые отчёты
├── run.sh                 # скрипт запуска
├── requirements.txt       # зависимости
└── README.md
```

## Установка

Нужен Python 3. Ставим зависимости:

```bash
pip install -r requirements.txt
```

Их всего две: `pymorphy3` для лемматизации русского текста и `pytest` для тестов.

## Запуск

Сначала положите письма в папку `data/inbox/` — именно в неё саму, а не во вложенную
папку. Затем запустите:

```bash
bash run.sh
```

Можно и напрямую, из корня проекта:

```bash
python -m src.mail_classifier.main
```

Когда программа отработает, вы найдёте:
- разложенные по категориям письма в `data/output/<категория>/`;
- лог работы в папке `logs/`;
- итоговый отчёт в `reports/summary_report.txt`.

## Тесты

```bash
pytest
```

## Как мы справляемся со «сложными» файлами

Мы заранее знали, что среди писем будут ловушки, и подготовились. Ни одна из этих
ситуаций не роняет программу — файл уходит в технический карантин, а причина
записывается в лог:

- пустой файл;
- бинарный файл или изображение (`.bin`, `.jpeg` и подобные);
- файл с неподдерживаемым расширением;
- файл, который не читается ни в одной из поддерживаемых кодировок;
- слишком большой файл;
- системные файлы вроде `.DS_Store`.
